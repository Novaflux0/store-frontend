# @agency/types

API contract types and constants shared by `storefront`, `admin` and `backend`: response
bodies, the RFC 9457 error shape, roles, route paths and header names. Request
bodies are not here: they are inferred from the Zod schemas in `@agency/validation`.

## Exports

| Export                                                                                                                                                                        | Kind            | Notes                                                                                                                                                                             |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ProblemDetails`                                                                                                                                                              | type            | RFC 9457 error: `type`, `title`, `status`, `detail`, `instance?`, `traceId`, `errors?` (field path to messages)                                                                   |
| `PROBLEM_TYPES`, `ProblemType`                                                                                                                                                | const, type     | Problem slugs (last segment of `ProblemDetails.type`), e.g. `PROBLEM_TYPES.invalidOrExpiredToken` is `'invalid-or-expired-token'`; each entry documents its usual status          |
| `PROBLEM_JSON_CONTENT_TYPE`                                                                                                                                                   | const           | `'application/problem+json'`                                                                                                                                                      |
| `HealthResponse`, `HealthStatus`, `HealthIndicatorStatus`, `HealthIndicatorResults`                                                                                           | types           | Same shape as @nestjs/terminus                                                                                                                                                    |
| `CreateLeadResponse`                                                                                                                                                          | type            | 201: `{ id, status: 'received' }`                                                                                                                                                 |
| `NewsletterSubscribeResponse`                                                                                                                                                 | type            | 202: `{ status: 'pending_confirmation' }` (same for every email, to prevent enumeration)                                                                                          |
| `NewsletterConfirmResponse`                                                                                                                                                   | type            | 200: `{ status: 'confirmed' }`                                                                                                                                                    |
| `NewsletterUnsubscribeResponse`                                                                                                                                               | type            | 200: `{ status: 'unsubscribed' }` (same whether or not the token matched)                                                                                                         |
| `JobApplicationResponse`                                                                                                                                                      | type            | 202: `{ id, status: 'received' }` (the CV is scanned asynchronously)                                                                                                              |
| `UploadUrlResponse`                                                                                                                                                           | type            | 201: `{ fileId, uploadUrl, method: 'PUT', headers, expiresAt }`; send `headers` unchanged with the PUT                                                                            |
| `CursorPage<T>`                                                                                                                                                               | type            | `{ items, nextCursor: string \| null }`                                                                                                                                           |
| `ROLES`, `Role`                                                                                                                                                               | const, type     | `'SUPER_ADMIN' \| 'ADMIN' \| 'STAFF' \| 'CLIENT'`                                                                                                                                 |
| `STAFF_ROLES`, `StaffRole`, `isStaffRole()`                                                                                                                                   | const, type, fn | Roles that must enrol TOTP                                                                                                                                                        |
| `API_PREFIX`                                                                                                                                                                  | const           | `'/api/v1'`                                                                                                                                                                       |
| `API_ROUTES`, `ApiRoute`, `apiPath()`, `fillRoute()`, `RouteParams`                                                                                                           | const, type, fn | Paths relative to the prefix; `apiPath(API_ROUTES.leads)` is `/api/v1/leads`                                                                                                      |
| `API_HEADERS`                                                                                                                                                                 | const           | `Idempotency-Key`, `X-Client-IP`, `X-Client-IP-Timestamp`, `X-Client-IP-Signature`, `X-Request-Id`, `Cf-Access-Jwt-Assertion`, `X-Revalidate-Timestamp`, `X-Revalidate-Signature` |
| `AdminMe`, `StaffUser`, `TeamResponse`, `SessionInfo`, `LoginResponse`, `AuthTokens`, `MfaEnroll*Response`, `RecoveryCodesResponse`, `StepUpResponse`, `JwksResponse`         | types           | Staff auth and team responses (ADR 0015)                                                                                                                                          |
| `DashboardSummary`, `LeadSummary`, `LeadDetail`, `LeadNote`, `Subscriber`, `ApplicationSummary`, `ApplicationDetail`, `SignedUrlResponse`, `AuditEntry`, `ActorRef`           | types           | Admin data screens                                                                                                                                                                |
| `ContentEntrySummary`, `ContentEntryDetail`, `ContentRevision`, `PreviewLinkResponse`, `PublishedContent`, `ContentPreview`, `MediaAsset`, `MediaVariant`, `SettingsDocument` | types           | CMS, media and settings (ADRs 0016, 0017)                                                                                                                                         |
| `CACHE_TAGS`, `RevalidateRequest`                                                                                                                                             | const, type     | Storefront cache tags (`settings`, `content:<type>`, `content:<type>:<slug>`) and the signed revalidate body                                                                      |

Timestamps in responses are ISO 8601 strings in UTC.

Clients branch on the problem slug (`PROBLEM_TYPES`), never on `title` or `detail`.
Add a slug to `PROBLEM_TYPES` before the API starts returning it.

Everything here is free of runtime dependencies, so browser code can import it
without bundle cost beyond the constants it uses.

## Build

Same dual CommonJS / ESM build as `@agency/validation`; see its README. Turbo builds
it before dependants (`^build`).
